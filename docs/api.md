# API endpoints

The real list of endpoints. Base path: `/api/v1`. Conventions are in `CLAUDE.md`, section 10. The machine-readable version is `docs/openapi.json`, generated by `pnpm api:spec`.

Every POST, PUT, PATCH and DELETE needs the `X-CSRF-Token` header matching the `hms_csrf` cookie (`__Secure-hms_csrf` in production). Errors use `{ "error": { "code", "message", "details" } }`.

| Method | Path | Permission | Notes |
| --- | --- | --- | --- |
| GET | `/health` | Public | Liveness and database check. 200 `{ "status": "ok" }`, 500 when the database does not answer. |
| GET | `/auth/csrf` | Public | Issues a CSRF token (bound to the current session, if any) and sets the CSRF cookie. The login screen calls it first. |
| POST | `/auth/login` | Public | Body `{ username, password }`. Either `{ status: "signed_in", ...profile, csrfToken }` with the session and CSRF cookies set, or `{ status: "challenge", step, expiresAt }` with an httpOnly `hms_login` cookie (path `/api/v1/auth/login`, 10 minutes) when the user owes another step first: `change_password` after an admin set the password, then `totp_setup` (two-factor required by the user's permissions and not on yet) or `totp_verify` (two-factor on). Every failure is 401 `LOGIN_FAILED`. Limited to 5 per minute per username and IP. |
| POST | `/auth/login/password` | Public (challenge cookie) | The `change_password` step. Body `{ newPassword }` (10 or more characters, not the current one: 422 `PASSWORD_REUSED`). Answers like `/auth/login`. 401 `LOGIN_CHALLENGE_INVALID` for a missing, used, expired or outdated challenge. Limited to 3 per hour per challenge. |
| POST | `/auth/logout` | `auth.session.manage-own` | Ends the session and clears both cookies. 204. |
| GET | `/auth/login/totp/setup` | Public (challenge cookie) | The `totp_setup` step: `{ secret, otpauthUri, qrCode }` (an SVG data URL). Asking again shows the same secret. |
| POST | `/auth/login/totp/setup` | Public (challenge cookie) | Body `{ code }` (6 digits, spaces ignored). Switches two-factor on and answers like `/auth/login`, with `recoveryCodes` (10, shown once). 422 `TOTP_INVALID` counts toward the lockout. Login limit per challenge. |
| POST | `/auth/login/totp` | Public (challenge cookie) | The `totp_verify` step. Body `{ code }` or `{ recoveryCode }`, exactly one. A code is accepted once (its 30 second step is recorded); a recovery code works once. 422 `TOTP_INVALID` counts toward the lockout: 5 wrong codes lock the account for 15 minutes. Login limit per challenge. |
| GET | `/auth/me` | `auth.session.manage-own` | The signed-in user, hospital, permission codes and session expiry, and `breakGlass` (`{ grantId, expiresAt }` or null). During break-glass `hospital` is the hospital opened. |
| POST | `/auth/password` | `auth.session.manage-own` | Body `{ currentPassword, newPassword }`. Ends your other sessions and keeps this one. 422 `CURRENT_PASSWORD_WRONG` (audited) or `PASSWORD_REUSED`. Limited to 3 per hour per session. 204. |
| GET | `/auth/sessions` | `auth.session.manage-own` | `{ data }`: your open sessions (not ended, idle or expired) with created, last seen, expiry, IP address, user agent and `current`. |
| POST | `/auth/sessions/:id/end` | `auth.session.manage-own` | Ends one of your other sessions. 422 `CURRENT_SESSION` for the one in use (sign out instead); 404 for another user's or an ended session. 204. |
| GET | `/auth/two-factor` | `auth.session.manage-own` | `{ enabled, required, recoveryCodesLeft }`. Required when the user holds `platform.hospital.manage`, `users.user.manage` or `tariffs.tariff.manage`. |
| POST | `/auth/two-factor/setup` | `auth.session.manage-own` | A new pending secret: `{ secret, otpauthUri, qrCode }`. 409 `TWO_FACTOR_STATE` when already on. |
| POST | `/auth/two-factor/enable` | `auth.session.manage-own` | Body `{ code }`. Switches it on and returns `{ recoveryCodes }` once. 422 `TOTP_INVALID` (audited). Login limit per session. |
| POST | `/auth/two-factor/recovery-codes` | `auth.session.manage-own` | Body `{ code }`. New `{ recoveryCodes }`; the unused ones stop working. |
| POST | `/auth/two-factor/disable` | `auth.session.manage-own` | Body `{ code }`. 422 `TWO_FACTOR_REQUIRED` when the user's permissions need it. 204. |
| POST | `/auth/sessions/end-others` | `auth.session.manage-own` | Ends all your sessions except this one. `{ ended }`. |

## Break-glass access

A DevMSR super admin's read-only access to one hospital, tied to their session, for 1 hour. While it is open the session reaches that hospital with `BREAK_GLASS_PERMISSIONS` (patients, billing account, masters, rates, beds and audit, all read only), and every audit event of the session carries `breakGlassId`. It ends early with `POST /break-glass/current/end` or at sign-out.

| Method | Path | Permission | Notes |
| --- | --- | --- | --- |
| GET | `/break-glass/hospitals` | `platform.break-glass.use` | `{ data }`: active hospitals `{ id, code, name }`. |
| POST | `/break-glass` | `platform.break-glass.use` | Body `{ hospitalId, reason }` (reason 20 to 500 characters). 201 with the grant. Audited in that hospital (`platform.break-glass.started`), and every user there holding `users.user.manage` is notified. 404 for an unknown or inactive hospital; 409 `BREAK_GLASS_ACTIVE` when the session already has one. |
| POST | `/break-glass/current/end` | `platform.break-glass.use` | Ends this session's access. 204; 404 when none is open. |
| GET | `/break-glass` | `audit.event.read` | This hospital's break-glass history, newest first: `{ id, hospital, user, reason, createdAt, expiresAt, endedAt, active }`. |

## Admin setup

Lists take `?page=1&pageSize=50&q=text&includeInactive=true` and return `{ data, page, pageSize, total }`. Records of another hospital are 404. Codes are stored in capitals.

| Method | Path | Permission | Notes |
| --- | --- | --- | --- |
| GET | `/users` | `users.user.manage` | Staff users of the hospital with their roles, lock state, `mustChangePassword` and last sign-in. `?permission=opd.queue.read-own` lists only users holding that permission. Never lists platform users. |
| POST | `/users` | `users.user.manage` | Body `{ username, displayName, password, roleCodes }`. 409 if the username is taken, 422 `ROLE_NOT_ASSIGNABLE` for a role outside the hospital. |
| PATCH | `/users/:id` | `users.user.manage` | Any of `{ displayName, isActive, roleCodes }`. Deactivating ends the user's sessions. 422 `SELF_CHANGE_NOT_ALLOWED` for your own roles or status. |
| POST | `/users/:id/two-factor/reset` | `users.user.manage` | For a lost phone: switches the user's two-factor off, revokes their recovery codes and ends their sessions. They set it up again at the next sign-in if their role needs it. 204. Not for your own account. |
| POST | `/users/:id/password` | `users.user.manage` | Body `{ password }` (10 or more characters). The user must replace it at the next sign-in. Unlocks the account and ends its sessions. 204. Not for your own account. Limited to 3 per hour per account. |
| GET | `/roles` | `users.user.manage` | The hospital's roles with their permission codes. |
| GET | `/hospital-profile` | `masters.data.read` | Name, code, address, PIN code, phone and email, as printed on bills. |
| PATCH | `/hospital-profile` | `settings.hospital.manage` | Any of `{ name, addressLine, city, state, pincode, phone, email }`. Empty optional fields become null. |
| GET | `/departments` | `masters.data.read` | |
| POST | `/departments` | `masters.data.manage` | Body `{ code, name }`. 409 for a code in use. |
| PATCH | `/departments/:id` | `masters.data.manage` | Any of `{ name, isActive }`. |
| GET | `/doctors` | `masters.data.read` | With department name and linked username. `?departmentId=` filters. |
| POST | `/doctors` | `masters.data.manage` | Body `{ fullName, departmentId, qualification?, registrationNumber?, userId?, isVisiting? }`. 422 `REFERENCE_INVALID` for an inactive or unknown department, `DOCTOR_LOGIN_INVALID` for a login that is not an active doctor login or is linked already. |
| PATCH | `/doctors/:id` | `masters.data.manage` | Any of the create fields and `isActive`. `userId: null` unlinks the login. |
| GET | `/room-categories` | `masters.data.read` | |
| POST | `/room-categories` | `masters.data.manage` | Body `{ code, name }`. |
| PATCH | `/room-categories/:id` | `masters.data.manage` | Any of `{ name, isActive }`. |
| GET | `/wards` | `masters.data.read` | With room category name and bed count. |
| POST | `/wards` | `masters.data.manage` | Body `{ code, name, roomCategoryId? }`. The ward joins the hospital's branch. |
| PATCH | `/wards/:id` | `masters.data.manage` | Any of `{ name, roomCategoryId, isActive }`. 422 `BED_OCCUPIED` when retiring a ward with a patient in it. |
| GET | `/wards/:id/beds` | `masters.data.read` | `{ data }` with every bed of the ward, active or not. |
| POST | `/wards/:id/beds` | `masters.data.manage` | Body `{ code }`. New beds are free. 409 for a code already in this ward. |
| PATCH | `/beds/:id` | `masters.data.manage` | Body `{ isActive }`: retire or restore. 422 `BED_OCCUPIED` for an occupied bed. |
| GET | `/service-items` | `tariffs.tariff.read` | Everything the hospital charges for, with the rate that applies today (`currentRate`, or null). `?kind=` and `?doctorId=` filter. |
| POST | `/service-items` | `tariffs.tariff.manage` | Body `{ code, name, kind, doctorId?, roomCategoryId? }`. Only a consultation has a doctor, only room rent and nursing have a room category. |
| PATCH | `/service-items/:id` | `tariffs.tariff.manage` | Any of `{ name, isActive }`. |
| GET | `/service-items/:id/rates` | `tariffs.tariff.read` | `{ data }`: the full rate history, newest first, cancelled rates included (`cancelledAt`, `cancelReason`). |
| POST | `/service-items/:id/rates` | `tariffs.tariff.manage` | Body `{ ratePaise, taxRateBp, effectiveFrom }`. Starts today or later (IST) and after the current rate's start; the current rate ends the day before. 422 `RATE_DATE_INVALID` otherwise. |
| POST | `/service-items/:id/rates/:rateId/cancel` | `tariffs.tariff.manage` | Body `{ reason }` (3 to 200 characters). Cancels the latest rate before it starts; the rate before it carries on. 200 with the cancelled rate. 422 `RATE_NOT_CANCELLABLE` for a rate that has started, is followed by a later rate, or is already cancelled. |

## Patients

Patient names, phone numbers, Aadhaar and ABHA numbers never go in a URL, so search is a POST. Aadhaar and ABHA numbers are stored encrypted and only their last 4 digits are ever returned. Errors about duplicates name only patient IDs and UHIDs.

| Method | Path | Permission | Notes |
| --- | --- | --- | --- |
| POST | `/patients/search` | `patients.patient.read` | Body `{ q, page?, pageSize? }`. `q` is a UHID (any case), the number part of one (`123` finds `DEMO-2026-000123`), a mobile number, a name (2 characters or more), or an Aadhaar or ABHA number. Paged list of summaries. Audited without the search text. |
| POST | `/patients/duplicate-check` | `patients.patient.create` | Body `{ fullName, dateOfBirth? or ageYears?, phone?, aadhaar?, abhaNumber? }`. `{ blocking, possible }`: same Aadhaar or ABHA blocks; same mobile, or same name with a birth year within one year, is possible. Each match lists its `reasons`. |
| POST | `/patients` | `patients.patient.create` | Needs `Idempotency-Key`. Body: `fullName`, `sex`, `ageYears` or `dateOfBirth`, `phone` (10-digit Indian mobile), optional address, guardian (relation and name together), emergency contact, `aadhaar`, `abhaNumber`, and `acknowledgedDuplicateIds`. Gives the next UHID (`<CODE>-<YEAR>-<6 digits>`, gapless per calendar year). 409 `DUPLICATE_PATIENT` for the same Aadhaar or ABHA; 409 `POSSIBLE_DUPLICATE` for a possible duplicate not acknowledged. |
| GET | `/patients/:id` | `patients.patient.read` | The record, with `aadhaarLast4` and `abhaNumberLast4`. Every view writes an audit event. |
| PATCH | `/patients/:id` | `patients.patient.update` | Any registration field. `null` clears an optional one; an age replaces the date of birth. The UHID never changes. A new Aadhaar or ABHA number runs the duplicate block again. The audit event lists the field names, not values. |

## Billing and payments

Money is in paise (integers). Rules are in `docs/billing-rules.md`. Routes marked "Needs `Idempotency-Key`" return the stored response when the same key is sent again. Records of another hospital are 404.

| Method | Path | Permission | Notes |
| --- | --- | --- | --- |
| POST | `/patients/:id/charges` | `billing.charge.create` | Needs `Idempotency-Key`. Body `{ serviceItemId, quantity, serviceDate? }` (quantity 1 to 999, date in IST, today or earlier). Snapshots the rate and tax rate in force on that date. 422 `RATE_MISSING` when the item has no rate then, `REFERENCE_INVALID` for an inactive item. |
| GET | `/patients/:id/charges` | `billing.account.read` | `{ data }`: the patient's charges. `?status=pending` or `billed`. A pending charge on a draft bill has its `invoiceId`. |
| GET | `/patients/:id/account` | `billing.account.read` | The patient as printed on bills, unbilled charges (count and amount), bills with paid and due, receipts, deposit held and total due. Audited. |
| POST | `/invoices` | `billing.invoice.create` | Needs `Idempotency-Key`. Body `{ patientId, chargeIds }` (1 to 500 pending charges of that patient, not on another draft). Creates a draft with one line per charge: tax per line, CGST and SGST halves, total rounded to the rupee with a round off. 422 `CHARGE_UNAVAILABLE` otherwise. |
| GET | `/invoices` | `billing.account.read` | Paged bill summaries, newest first. `?status=draft`, `issued` or `discarded`, `?patientId=`. |
| GET | `/invoices/:id` | `billing.account.read` | The bill with lines, totals, paid and due, and (once issued) the hospital and patient as they were at issue. Audited. |
| POST | `/invoices/:id/issue` | `billing.invoice.issue` | Needs `Idempotency-Key`. Gives the next number (`<CODE>/INV/<FY>/<6 digits>`, gapless per financial year), snapshots the hospital and patient, marks the charges billed and locks the bill for good. 200. 409 `INVOICE_LOCKED` if it is not a draft. |
| POST | `/invoices/:id/discard` | `billing.invoice.create` | Discards a draft and releases its charges. The draft is kept. 200. 409 `INVOICE_LOCKED` if it is not a draft. |
| POST | `/cash-shifts` | `payments.shift.manage-own` | Body `{ openingCashPaise }`. Opens the cashier's shift. 409 `SHIFT_ALREADY_OPEN`. |
| GET | `/cash-shifts/current` | `payments.shift.manage-own` | `{ shift }`: the cashier's open shift with takings by mode and the cash expected in the drawer, or null. |
| POST | `/cash-shifts/:id/close` | `payments.shift.manage-own` | Body `{ countedCashPaise, differenceReason? }`. A count that differs from the expected cash needs a reason (3 to 200 characters); the difference is recorded. Only your own shift (another cashier's is 404). 200. 409 `SHIFT_CLOSED`. |
| GET | `/cash-shifts` | `reports.collection.read` | Paged shifts of every cashier, newest first, for finance. |
| POST | `/payments` | `payments.receipt.create` | Needs `Idempotency-Key`. Body `{ invoiceId, mode, amountPaise, reference?, cardLast4?, bankName? }`. Cash needs nothing more; UPI the UTR; card the approval code and last 4 digits; bank transfer or cheque the reference and bank. Up to the amount due on an issued bill. Gives a receipt number (`<CODE>/RCT/<FY>/<6 digits>`). 422 `SHIFT_REQUIRED`, `BILL_NOT_ISSUED`, `AMOUNT_EXCEEDS_DUE`. |
| POST | `/deposits` | `payments.deposit.create` | Needs `Idempotency-Key`. Body `{ patientId, mode, amountPaise, ... }` with the same details as a payment. A numbered receipt for money held for the patient; not revenue. 422 `SHIFT_REQUIRED`. |
| POST | `/invoices/:id/apply-deposit` | `payments.receipt.create` | Needs `Idempotency-Key`. Body `{ amountPaise }`. Sets held deposit against an issued bill, oldest deposit first. No money moves, so no shift is needed. 200. 422 `BILL_NOT_ISSUED`, `AMOUNT_EXCEEDS_DUE`, `NO_DEPOSIT_HELD`. |
| GET | `/receipts/:id` | `billing.account.read` | The receipt with the hospital, the patient, what it was set against and, for a deposit, what is still held. |

## Error codes

| Code | Status | When |
| --- | --- | --- |
| `VALIDATION_FAILED` | 400 | Input does not match the route's schema. `details` lists `{ location, path, message }`. |
| `UNAUTHENTICATED` | 401 | No valid session. |
| `SESSION_EXPIRED` | 401 | Idle for 15 minutes or past the 12 hour maximum. |
| `LOGIN_FAILED` | 401 | Any failed login. |
| `LOGIN_CHALLENGE_INVALID` | 401 | A sign-in step without a valid challenge: missing, already used, older than 10 minutes, or older than the account's last password change. |
| `CSRF_FAILED` | 403 | Missing, mismatched or wrongly signed CSRF token. |
| `PERMISSION_DENIED` | 403 | The user lacks the route's permission code. |
| `NOT_FOUND` | 404 | No such record in the user's hospital, including records of other hospitals. |
| `CONFLICT` | 409 | The record already exists. |
| `IDEMPOTENCY_KEY_REQUIRED` | 400 | A financial POST without a valid `Idempotency-Key`. |
| `IDEMPOTENCY_KEY_REUSED` | 422 | The key was used for a different request. |
| `IDEMPOTENCY_IN_PROGRESS` | 409 | The first request with this key is still running. |
| `RATE_LIMITED` | 429 | Too many requests. `Retry-After` gives the wait in seconds. |
| `SELF_CHANGE_NOT_ALLOWED` | 422 | An admin tried to change their own roles, status or password through user management. |
| `ROLE_NOT_ASSIGNABLE` | 422 | A role code that is not a role of this hospital. |
| `DOCTOR_LOGIN_INVALID` | 422 | The login to link to a doctor is not an active doctor login of this hospital, or is linked already. |
| `REFERENCE_INVALID` | 422 | A chosen department, room category, doctor or service item is inactive or does not exist. |
| `RATE_DATE_INVALID` | 422 | A new rate starts in the past, or not after the current rate's start. |
| `BED_OCCUPIED` | 422 | Retiring a bed or ward that has a patient in it. |
| `RATE_NOT_CANCELLABLE` | 422 | Cancelling a rate that has started, is followed by a later rate, or is already cancelled. |
| `DUPLICATE_PATIENT` | 409 | The Aadhaar or ABHA number belongs to another patient of the hospital. `details.matches` lists `{ id, uhid }` only. |
| `POSSIBLE_DUPLICATE` | 409 | A patient with the same mobile, or the same name and birth year, exists and was not acknowledged. `details.matches` lists `{ id, uhid }` only. |
| `RATE_MISSING` | 422 | A charge for a service with no rate on the service date. |
| `CHARGE_UNAVAILABLE` | 422 | A charge chosen for a bill is billed, on another draft, or belongs to another patient. |
| `INVOICE_LOCKED` | 409 | Issuing or discarding a bill that is no longer a draft. |
| `SHIFT_REQUIRED` | 422 | Taking money without an open shift of your own. |
| `SHIFT_ALREADY_OPEN` | 409 | Opening a second shift. |
| `SHIFT_CLOSED` | 409 | Closing a shift that is already closed. |
| `AMOUNT_EXCEEDS_DUE` | 422 | A payment or deposit use larger than the bill's amount due. |
| `NO_DEPOSIT_HELD` | 422 | Using more deposit than the patient has held. |
| `BILL_NOT_ISSUED` | 422 | Paying a draft or discarded bill. |
| `PASSWORD_REUSED` | 422 | A new password the same as the current one. |
| `CURRENT_PASSWORD_WRONG` | 422 | Changing your own password with a wrong current password. |
| `CURRENT_SESSION` | 422 | Ending the session you are using through `/auth/sessions/:id/end`. |
| `TOTP_INVALID` | 422 | A wrong, old or already used two-factor code, or an unknown or used recovery code. |
| `TWO_FACTOR_REQUIRED` | 422 | Switching two-factor off when your permissions need it. |
| `TWO_FACTOR_STATE` | 409 | Two-factor setup that does not match its state: already on, or not started. |
| `BREAK_GLASS_ACTIVE` | 409 | Starting break-glass access in a session that already has one open. |
| `INTERNAL_ERROR` | 500 | Anything unexpected. Details are logged with the `X-Request-Id`, never returned. |
